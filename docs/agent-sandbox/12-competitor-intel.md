> 对应计划「可协助做判断 · 第 12 项」，落实报告 18.1「从『找同行』改为『找替代方案』」。

> 全部标注为「转引」。按下面的复核纪律，首次季度复核时需逐条替换为带链接与检索日期的一手记录。

## 1. 组织方式：按「客户问题 → 解法路径」而非「按赛道」

**客户问题**：让 Agent 安全地对数据库做写操作（能试错、可回滚、经审批合并回生产）。

穷举解法路径，每条至少两个代表玩家：

| 路径 | 代表玩家 | 是否覆盖存量异构库 |
| --- | --- | --- |
| P1 CDM/TDM 克隆 | Delphix、Actifio(Google)、本土 CDM 厂商 | 是 |
| P2 云原生数据库分支 | Neon、Supabase、PlanetScale | 否 |
| P3 版本化数据库 | Dolt / DoltgreSQL | 否（需迁到其引擎） |
| P4 数仓零拷贝克隆 | Databricks Delta、Snowflake | 否（数仓侧） |
| P5 开源瘦克隆 | Postgres.ai / DLE | 部分（仅 PG） |
| P6 云厂商快速克隆 | PolarDB、Aurora、TiDB、GaussDB、OceanBase | 部分（仅其自有云） |
| P7 合成数据替代真实数据 | Tonic.ai、K2view | 是（但不是同一价值） |
| P8 只读 + 人工执行 | Delphix MCP、Cohesity Gaia、Rubrik | 是（但不闭环） |
| P9 **客户自建土办法** | ZFS/LVM 快照 + 脚本 | 是 —— **往往是最真实的竞争对手** |
| P10 干脆不用 Agent 碰数据库 | —— | 是（现状，也是最大竞争者） |

> P9 与 P10 是第一版报告完全缺席、但在客户现场最常遇到的「竞品」。
> 13 文档的访谈提纲专门设计了问题来暴露它们。

## 3. 情报缺口（必须补的三项）

1. **C13 本土 CDM 厂商**：信创招标中最可能正面相遇，目前完全没有对比数据，建议单独立项调研；
2. **各家「合并回主干」的真实颗粒度**：这是差异化论证的关键，但目前全部是转引，
   建议用 07 文档的横向基准测试实测，而不是引用宣传文案；
3. **C14/C15 的真实占比**：需要通过访谈量化，「客户自己拿快照攒一套」的普及度直接决定定价空间。

## 4. 复核纪律

| 项 | 要求 |
| --- | --- |
| 频率 | AI 相关能力**每季度**复核一次；重大收购/发布随时更新 |
| 形式 | 直接更新本表，保留历史版本（git history 即可），不另建系统 |
| 证据 | 每条结论必须有链接 + 检索日期 + 证据类型；缺任一项标记为「待核实」 |
| **证伪动作** | 每写下一条「没有人做过 X」，必须先记录尝试推翻它的检索路径；未记录的此类结论一律不得写入对外材料 |

## 5. 对外表述红线

- 禁用「唯一」「全球首创」「全行业空白」；
- 统一口径：**「Agent 可写数据库分支已被云原生数据库验证并商用，但只能作用于其自有引擎；
  企业核心数据仍在 Oracle/DB2/SQL Server/信创库里，这部分的 Agent 可写分支目前没有成熟商用产品。」**
- 这个表述可被证伪、可被验证，且客户提到 Neon 时不会陷入被动。
