# 00 · 假设清单（Assumption Ledger）

> 落实报告 18.2「区分事实、推断与假设」。
> **本清单是第二轮复核的产物**：第一轮的三个致命矛盾，全部源于未被显式记录的假设。
> 纪律：任何技术文档不得依赖未登记在本表的假设；新增假设必须同时填写「若不成立的后果」与「验证方式」。

## 类型标注

| 标注 | 含义 |
| --- | --- |
| **事实** | 有内部资料或实测支撑，可引用 |
| **推断** | 由事实推导，逻辑可检验，但未直接验证 |
| **假设** | 尚无证据，方案依赖它成立 —— **这一类必须逐条验证** |

## 使用方式

1. **写文档前**：检查所依赖的前提是否已在本表登记，未登记则先登记；
2. **评审时**：只讨论「假设」类条目，「事实」类不占用会议时间；
3. **验证后**：更新状态列并注明证据位置，**不得删除历史行**；
4. **状态为「存在反证」或「已证伪」的假设，对应的设计必须修改**，不允许带着已知反证继续排期。
