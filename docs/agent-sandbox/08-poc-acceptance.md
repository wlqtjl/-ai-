# 08 · POC 验收指标与自动化校验

> 对应计划「可立即产出 · 第 8 项」，落实报告 18.5「预先定义可量化的成功判据」。
> 自动化检查：[`tools/poc_gate.py`](tools/poc_gate.py)　指标模板：[`templates/poc-metrics.template.json`](templates/poc-metrics.template.json)

## 1. 规则

1. 指标在 POC **启动前**与客户共同确认并冻结，事后不得调整口径；
2. 分两档：**红线指标（redline）** 任一不达标即 POC 判负；**目标指标（target）** 不达标记为待改进；
3. 结论由脚本产出，不由人主观判断（避免用「客户觉得不错」结题）。

## 2. 指标表

| 维度 | 指标 | 档位 | 目标值 | 说明 |
| --- | --- | --- | --- | --- |
| 安全 | 源端新增权限/挂载/代理数量 | **红线** | = 0 | 对应第七部分设计红线，破坏即失去核心优势 |
| 准确性 | ChangeSet 与实际变更一致率 | **红线** | = 100% | 漏报是安全问题；用 `compare_changesets.py` 判定 |
| 可靠 | 合并/回滚失败时生产库受影响次数 | **红线** | = 0 | 由「合并前建回退点 + 失败自动回退」保障 |
| 安全 | Agent 成功自审自批的次数 | **红线** | = 0 | 权限模型有效性的直接验证 |
| 安全 | 到期未回收的沙盒数（含孤儿资源） | **红线** | = 0 | 资源泄漏与凭据残留 |
| 效率 | `near_current` 创建耗时 P95 | 目标 | < 5 分钟 | 需沙盒节点与存储同机房 |
| 效率 | 端到端耗时较现有人工流程降幅 | 目标 | ≥ 80% | 与客户共同测定基线 |
| 规模 | 单集群并发存活沙盒上限 | 目标 | ≥ 100 | 压测得出 |
| 效率 | 创建耗时预估准确度 | 目标 | 误差 ≤ 50% | SLA 承诺可信度 |
| 可靠 | 合并回切成功率 | 目标 | ≥ 99% | 排除因冲突被正常拒绝的情况 |
| 隔离 | 备份/容灾任务耗时劣化 | 目标 | ≤ 5% | 验证队列隔离（06 文档） |
| 成本 | 单沙盒平均存储增量 / 全量克隆 | 目标 | ≤ 5% | 零拷贝的价值证明 |
| 合规 | 交付沙盒中脱敏默认开启的比例 | 目标 | = 100% | 关闭需 `security_admin` 授权并留痕 |

## 3. 使用方式

```bash
# 1. 复制模板，POC 期间由测试脚本或人工填入实测值
cp templates/poc-metrics.template.json /tmp/poc-run-01.json

# 2. 产出判定结论
python3 tools/poc_gate.py /tmp/poc-run-01.json

# 3. 回归自测（内置通过/红线失败/目标未达三种样本）
python3 tools/poc_gate.py --self-test
```

退出码：`0` 通过；`1` 红线不达标（POC 判负）；`3` 红线通过但存在目标未达（有条件通过）。

## 4. 未达标时怎么办

| 情况 | 处理 |
| --- | --- |
| 红线不达标 | POC 判负，回到设计而非调参；尤其「源端新增 ≠ 0」意味着方案违反了设计红线 |
| ChangeSet 一致率 < 100% | 直接触发 02 文档的 A/B 路径重新评估，可能需要换路径 |
| 规模未达 100 | 先查队列隔离与配额配置（06 文档），再考虑扩容，不要先改承诺 |
| 效率目标未达 | 优先检查网络拓扑（20M/s 的跨机房传输是最常见的原因） |
